So just looking at the last column: we would have expected 27, yet we got 23.8

Why?

It turns out, the AQI is a non-linear scale.

It maps particle concentrations to a scale of positive integer values, going from 0 to 500.

What the sensors measure is roughly particle concentrations, which is used a proxy to categorize air quality.

The idea is: if the concentration is in a given range, the AQI (air quality index) is between this and that value, and we draw a straight line to map concentration to AQI. Depending on the range, the slope changes and basically this is why it is non-linear. (It's piece-wise linear actually).

<details>
<summary>If one goes deeper...</summary>

The range tables actually map densities ($` \mu g / m^3 `$) to index values (not concentrations, that'd be $` N/m^3 `$) and what table to use also depends on the particle sizes.

For PM2.5 particles (that is, particles with diameter $` <= 2.5 \mu m'$), the table is

AQI Range | PM2.5 ($` \mu g / m^3 `$)
--|--
| 0–50     | 0–12.0       |
| 51–100   | 12.1–35.4    |
| 101–150  | 35.5–55.4    |
| 151–200  | 55.5–150.4   |
| 201–300  | 150.5–250.4  |
| 301–400  | 250.5–350.4  |
| 401–500  | 350.5–500.4  |

(if higher than 500.4, it's reported as 500+)

While the high grade sensors do catch, filter and weight particles, the ones used by the AireLibre project (e.g., PMS7003, listed above) mainly count particles and estimates sizes/masses by how the particles scatter light.

The PMS7003, in particular, measures PM1.0, PM2.5, and PM10.

The PM2.5 values are the ones mainly used to report AQI (sometimes with high contamination, the others are taken into account, but it's rare).

Furthermore, it's not the instantaneous ~~concentration~~ density that is used, but actually the average value over a time window. Again, this changes according to the max particle diameter, but for the PM2.5 a window of 24 hours is usually used. This means: AQI (for PM2.5) at time $`t`$ would be computed using the average particle density (of particles with diameter less then or equal to 2.5 microns) between times $`[t - \text{24h}, t)`$
</details>

But anyway...

That explains why the numbers do not exactly match: they would if it were a linear scale.

We could pull the raw particle concentration data (available in the API GET endpoint `/api/v1/measurements`) that's used to calculate the AQI values for each source...

but pulling the AQI values in one-hour intervals will be good enough.

We just have to keep in mind that, while the average across larger time periods -or even grouping multiple sensor data- might be useful to detect trends, using something like the AQI's P90 (90th quantile) would be a more representative metric.
